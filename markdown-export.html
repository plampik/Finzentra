ТЗ: Личный кабинет пользователя (ЛК) – MVP

1. Общее описание

Личный кабинет – это основная часть PWA-приложения, доступная пользователю после успешной авторизации.

Цель: Предоставить инструмент для раздельного учета финансов по нескольким проектам, ввода операций и анализа прибыли (P&L) и денежных потоков (Cash Flow). Роль пользователя: Владелец аккаунта (единственная роль в MVP).

2. Структура навигации ЛК

Интерфейс должен быть адаптирован под мобильные устройства (нижняя панель навигации) и десктоп (боковое меню).

Основные разделы:

  1. Дашборд (Главный экран с отчетами)
  2. Операции (Список и добавление доходов/расходов/налогов)
  3. Проекты (Управление направлениями деятельности)
  4. Настройки (Живые справочники категорий)

3. Функциональные требования по разделам

3.1. Раздел «Дашборд» (Отчеты)

Это ключевой экран для принятия решений.

  • FR-DASH-01: Глобальные фильтры
Период:* Месяц / Квартал / Год (выбор конкретного месяца/квартала/года).

Проекты:* Множественный выбор (чекбоксы). Варианты: «Все проекты», «Выбрать конкретные».

  • FR-DASH-02: Переключатель вида отчета
* Пользователь может переключать вид отображения данных: «Абсолютные цифры (₽)» или «Проценты (%)».
  • FR-DASH-03: Отображение в абсолютных цифрах (P&L / Cash Flow)
* Таблица или карточки с показателями: Доходы Итого, Расходы Итого, Налоги (ручной ввод), Чистая прибыль.

Важно:* Данные фильтруются в зависимости от выбранного метода (см. FR-DASH-05).

  • FR-DASH-04: Отображение в процентах
* Таблица, где «Доход Итого» принят за 100%.

* Все остальные строки (конкретные статьи доходов, расходы, налоги) отображаются как % от Дохода Итого.

Пример:* Доход Итого = 100%, Расход «Аренда» = 30%, Расход «Интернет» = 2%.

  • FR-DASH-05: Методы учета (логика фильтрации)
Кассовый метод (Cash Flow):* для расчета используются поле date_fact (дата фактического движения денег).

Метод начисления (P&L):* для расчета используется поле date_period (дата периода, к которому относится операция).

Реализация:* Переключатель «Кассовый метод / Метод начисления» на экране дашборда.

3.2. Раздел «Операции» (Доходы / Расходы / Налоги)

  • FR-OP-01: Список операций
* Отображение списка операций за выбранный период с возможностью поиска/фильтрации.

* В списке отображается: Дата факта, Сумма, Категория, Проект, Комментарий.

  • FR-OP-02: Форма добавления операции
Тип операции:* Доход / Расход / Налог (выбор из переключателя).

Сумма:* Числовое поле, только рубли (RUB).

Категория:* Выпадающий список из «живого» справочника (зависит от выбранного типа: доходы или расходы).

Проект:* Выпадающий список активных проектов пользователя.

Дата факта (date_fact):* Поле выбора даты. По умолчанию = сегодня. (Для Cash Flow).

Дата периода (date_period):* Поле выбора даты. По умолчанию = Дата факта. (Для P&L). Позволяет указать, что оплата, например, за следующий месяц.

Комментарий:* Текстовое поле (опционально, до 255 символов).

  • FR-OP-03: Редактирование и удаление
* Пользователь может изменить любую созданную операцию или удалить ее.

3.3. Раздел «Проекты»

  • FR-PRJ-01: Список проектов
* Отображение списка созданных проектов с признаком «Активен» / «В архиве».
  • FR-PRJ-02: Создание/Редактирование проекта
* Поля: Название проекта (обязательно, до 100 символов), Описание (опционально).

Важно:* Удаление проекта запрещено, если по нему есть операции. Проект можно только переименовать или отправить в «Архив» (скрыть из активных списков).

3.4. Раздел «Настройки» (Живые справочники)

  • FR-SET-01: Управление категориями доходов
* Просмотр списка. Возможность добавить новую категорию (ввод названия). Возможность удалить свою (пользовательскую) категорию.

* Системные категории (например, «Продажи») помечены как неудаляемые, но их можно скрыть или игнорировать.

  • FR-SET-02: Управление категориями расходов
* Аналогично доходам.

Важно:* По умолчанию в справочнике должны быть разделены «Коммуналка» и «Интернет» (как отдельные строки).

* Возможность добавлять и удалять свои категории расходов.

5. Критерии приемки (Acceptance Criteria)

AC-1: Добавление операции с разными датами (Сценарий куратора)

  • [ ] Пользователь может создать операцию «Расход».
  • [ ] Пользователь может установить «Дату факта» = 25 октября, а «Дату периода» = 1 ноября.
  • [ ] Операция успешно сохраняется и отображается в списке.

AC-2: Корректность отчетов (Кассовый метод vs Начисление)

  • [ ] При выборе на Дашборде «Кассовый метод» и периода «Октябрь», операция из AC-1 попадает в расходы октября.
  • [ ] При переключении на «Метод начисления» и периода «Ноябрь», та же операция попадает в расходы ноября.

AC-3: Отображение в процентах

  • [ ] При переключении Дашборда в режим «Проценты», сумма «Доход Итого» отображается как 100%.
  • [ ] Суммы статей расходов пересчитываются и отображаются как % от этого дохода (например, 15%, 30%).

AC-4: Живой справочник

  • [ ] Пользователь может зайти в Настройки, создать категорию расхода «Доставка», и она сразу становится доступной в выпадающем списке при создании новой операции.
  • [ ] Пользователь может удалить созданную им категорию «Доставка» (если по ней нет операций, или с предупреждением).
