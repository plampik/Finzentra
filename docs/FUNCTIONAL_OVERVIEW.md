# Finzentra — функциональное описание frontend

## 1. Назначение

Finzentra — русскоязычный адаптивный frontend для учета доходов, расходов и
налогов по проектам. Приложение помогает вручную вести операции и смотреть
сводные финансовые отчеты.

Текущая версия — клиентский демонстрационный прототип. Серверное API,
регистрация пользователей и синхронизация между устройствами не подключены.
Данные проектов, категорий и операций сохраняются в браузере.

## 2. Главный экран и доступ в кабинет

- При открытии приложения показывается публичный главный экран Finzentra.
- Кнопки входа и регистрации открывают соответствующие формы.
- Формы проверяют обязательные поля, формат email, длину пароля и совпадение
  паролей при регистрации.
- После отправки формы показывается пояснение, что для создания аккаунта или
  входа требуется backend. Форма не отправляет и не сохраняет пароль.
- Ссылка на демо открывает кабинет с демонстрационными данными без
  аутентификации.
- Из формы входа или регистрации можно вернуться на главный экран.

## 3. Кабинет

Кабинет состоит из четырёх разделов:

1. **Дашборд** — сводные показатели и финансовый отчёт.
2. **Операции** — журнал и форма создания/редактирования операций.
3. **Проекты** — список направлений бизнеса.
4. **Настройки** — справочники категорий.

На широком экране разделы доступны через боковую навигацию, на мобильном —
через нижнюю панель. В шапке доступны переход на главный экран, справка,
уведомления и создание операции. Уведомления сейчас показывают только
демонстрационное состояние «Новых уведомлений нет».

## 4. Дашборд и отчёт

### Фильтры

- Период: месяц, квартал или год. По умолчанию выбран текущий месяц.
- Проекты: мультивыбор активных проектов; изначально выбраны все активные.
- Метод учёта: метод начисления (P&L) или кассовый метод (Cash Flow).
- Вид значений в таблице отчёта: суммы в рублях или проценты от дохода.
  Карточки ключевых показателей остаются в рублях.
- Сравнение: опциональный выбор второго периода. По умолчанию предлагается
  предыдущий период того же типа.

### Показатели и расчёт

Для выбранных фильтров показываются доходы, расходы, налоги и чистая прибыль
(либо чистый денежный поток). Формула результата:

```text
доходы − расходы − налоги
```

- P&L выбирает операции по `date_period`.
- Cash Flow выбирает операции по `date_fact`.
- В расчёт попадают операции выбранных проектов с активными категориями.
- Разбивка отчёта группирует суммы по доходам, расходам и налогам; внутри
  группы категории сортируются по сумме по убыванию.
- В процентном режиме доля рассчитывается от общего дохода. При нулевом доходе
  вместо процента показывается `—`.
- Пустой отчёт отображает нулевые значения и позволяет перейти к созданию
  операции.

Расчёт выполняется в браузере функцией `buildReport` из `src/report.ts`.

## 5. Операции

Операция содержит тип, сумму, проект, категорию, дату факта, дату периода и
необязательный комментарий.

- Типы: `INCOME`, `EXPENSE`, `TAX`; по умолчанию — расход.
- Сумма должна быть положительной и иметь не более двух знаков после
  десятичного разделителя. В интерфейсе сумма вводится в рублях.
- Дата факта и дата периода обязательны и хранятся как календарные даты
  `YYYY-MM-DD`.
- При изменении даты факта дата периода следует за ней, пока пользователь не
  изменил дату периода вручную.
- Проект и категория выбираются из доступных активных записей; список
  категорий зависит от типа операции.
- Комментарий обрезается по краям и ограничен 255 символами.
- Список можно фильтровать по типу, проектам и периоду, искать по комментарию,
  сумме, обеим датам, проекту и категории. Фильтр периода журнала использует
  дату факта. Сначала отображаются более поздние операции.
- Перед удалением интерфейс просит подтверждение.

## 6. Проекты и категории

### Проекты

- Создание и переименование; название ограничено 100 символами, описание —
  255 символами.
- Архивирование и восстановление вместо физического удаления.
- В архиве проект сохраняет связь с ранее созданными операциями, но не
  предлагается для новых операций и обычного фильтра активных проектов.
- Счётчик операций показывается в карточке проекта.

### Категории

- Справочник разделён на расходы, доходы и налоги.
- Можно добавлять пользовательские категории и переключать их активность.
- Системную категорию нельзя удалить, но можно скрыть.
- Пользовательскую категорию, на которую ссылается операция, удалить нельзя;
  её можно скрыть. После удаления категории, которая нигде не используется,
  связанные операции отсутствуют.
- Названия категорий не должны повторяться внутри одного типа; проверка
  выполняется клиентом.

## 7. Демонстрационные данные и хранение

При первом запуске используются демонстрационные проекты, категории и
операции из `src/types.ts`. Они включают сценарии с различием дат факта и
периода и не являются производственными данными.

В браузере хранятся отдельные массивы:

- `finzentra_v2_projects`
- `finzentra_v2_categories`
- `finzentra_v2_transactions`

Структура записей проверяется при чтении. При ошибке чтения интерфейс
показывает уведомление и не перезаписывает повреждённое хранилище автоматически.
Данные не синхронизируются между пользователями или устройствами.

Production-сборка публикует PWA manifest, иконки и service worker для оболочки
и статических ресурсов; финансовые записи не являются частью кэша приложения.

## 8. Адаптивность и доступность

- Интерфейс перестраивается для телефонов, планшетов и больших экранов.
- На мобильных используется нижняя навигация, формы операций и выбора проектов
  открываются в диалоговых панелях.
- Для диалогов предусмотрены закрытие клавишей Escape, управление фокусом и
  блокировка фоновой прокрутки.
- Интерактивные элементы доступны с клавиатуры и имеют текстовые подписи для
  вспомогательных технологий.
- Учитываются системные безопасные зоны мобильных устройств и настройка
  уменьшения анимации.

## 9. Технологии и проверки

- React 19, TypeScript, Vite 8, Tailwind CSS 4.
- Основной интерфейс: `src/App.tsx`; разделы расположены в
  `src/components/`.
- Локальное состояние и сохранение: `src/store.ts`.
- Расчёт отчёта: `src/report.ts`; периоды: `src/period.ts`; форматирование:
  `src/format.ts`.
- CI GitHub Actions запускает `npm ci`, `npm run typecheck` и `npm run build`.
- Отдельный автоматизированный test runner в `package.json` не настроен.

## 10. Известные ограничения

- Нет регистрации, входа, сессий, ролей и разграничения доступа.
- Нет API-клиента, серверного хранилища и обмена данными.
- Нет серверной пагинации, авторитетного расчёта отчётов и синхронизации.
- Регистрация и вход — демонстрационные формы; тип аккаунта не отправляется
  серверу и не сохраняется.
- Уведомления являются заглушкой, а не системой событий.
- Клиентская валидация не заменяет серверную проверку прав и данных.

Схема фактических моделей, бизнес-правил, предлагаемого API и задач интеграции
описана в [руководстве для backend-разработчика](./BACKEND_HANDOFF.md).
