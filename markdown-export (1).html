ТЗ: Модуль «Операции» (Доходы, Расходы, Налоги)

1. Общее описание модуля

Модуль «Операции» — это ядро приложения, где пользователь ведет учет всех финансовых операций: доходов, расходов и налогов. Каждая операция привязана к проекту, категории и имеет две даты для поддержки кассового метода и метода начисления.

Цель модуля: Предоставить пользователю простой и понятный интерфейс для ввода финансовых данных с возможностью корректного учета временных разрывов между фактическим движением денег и периодом, к которому относится операция.

3. Функциональные требования

3.1. Добавление операции

IDТребованиеОписание
FR-OP-01Выбор типа операцииПользователь выбирает тип: Доход / Расход / Налог. Интерфейс формы адаптируется под выбранный тип (меняется список категорий).
FR-OP-02Поле «Сумма»Обязательное поле. Только положительные числа, максимум 2 знака после запятой. Валюта: рубли (₽).
FR-OP-03Поле «Дата факта» (date_fact)Обязательное поле. По умолчанию = сегодня. Это дата реального движения денег. Используется для отчета Cash Flow (кассовый метод).
FR-OP-04Поле «Дата периода» (date_period)Обязательное поле. По умолчанию = date_fact. Это дата периода, к которому относится операция. Используется для отчета P&L (метод начисления). Может быть в прошлом или будущем относительно date_fact.
FR-OP-05Поле «Проект»Обязательное поле. Выпадающий список активных проектов пользователя.
FR-OP-06Поле «Категория»Обязательное поле. Выпадающий список из живого справочника. Список зависит от типа операции: для дохода — категории с type='INCOME', для расхода — type='EXPENSE', для налога — type='TAX'.
FR-OP-07Поле «Комментарий»Необязательное текстовое поле, до 255 символов. Ручной ввод.
FR-OP-08Сохранение операцииПосле заполнения обязательных полей и нажатия «Сохранить» операция записывается в БД и отображается в списке.

5. Бизнес-правила

5.1. Две даты операции

Ситуацияdate_factdate_periodОтчет Cash FlowОтчет P&L
Обычная операция (оплата в день сделки)15.10.202615.10.2026Октябрь 2026Октябрь 2026
Авансовый платеж (оплата за следующий месяц)25.10.202601.11.2026Октябрь 2026Ноябрь 2026
Задержка выплаты (работа в октябре, оплата в ноябре)05.11.202631.10.2026Ноябрь 2026Октябрь 2026

5.2. Налоги

  • Налоги не рассчитываются автоматически. Пользователь вводит сумму вручную на основании квитанции из банка или ФНС.
  • Налоги хранятся как операции с типом «Налог» (в БД — отдельная таблица tax_transactions или в expense_transactions с категорией type='TAX').
  • Системные категории налогов (УСН 6%, УСН 15%, Страховые взносы, НДФЛ) создаются при инициализации БД с флагом is_system = true.

5.3. Живой справочник категорий

  • Пользователь может добавлять свои категории доходов, расходов и налогов.
  • Системные категории (например, «Аренда», «Коммуналка», «Интернет» — строго разные строки!) нельзя удалить, но можно скрыть (is_active = false).
  • Пользовательскую категорию можно удалить, только если по ней нет ни одной операции.

5.4. Валюта

  • Все суммы строго в рублях (RUB). Конвертация валют не предусмотрена.

8. Критерии приемки (Acceptance Criteria)

AC для US-OP-01, US-OP-02 (Добавление дохода/расхода с двумя датами)

  • [ ] Пользователь может выбрать тип операции «Доход» или «Расход».
  • [ ] Пользователь может установить date_fact = 25.10.2026 и date_period = 01.11.2026 (авансовый платеж).
  • [ ] Операция сохраняется и отображается в списке с обеими датами.
  • [ ] При выборе периода «Октябрь 2026» в отчете Cash Flow операция отображается в октябре.
  • [ ] При выборе периода «Ноябрь 2026» в отчете P&L операция отображается в ноябре.

AC для US-OP-03 (Добавление налога вручную)

  • [ ] Пользователь может выбрать тип операции «Налог».
  • [ ] Список категорий показывает только категории с type='TAX'.
  • [ ] Пользователь вводит сумму налога вручную (например, 45 957 ₽).
  • [ ] Операция сохраняется и учитывается в отчете P&L как расход на налоги.

AC для US-OP-04 (Фильтрация списка операций)

  • [ ] Пользователь может отфильтровать операции по проекту (один/несколько/все).
  • [ ] Пользователь может отфильтровать операции по периоду (месяц/квартал/год).
  • [ ] Пользователь может отфильтровать операции по типу (доходы/расходы/налоги).
  • [ ] Список отображается в хронологическом порядке (по date_fact).

AC для US-OP-05 (Редактирование и удаление)

  • [ ] Пользователь может открыть операцию, изменить любое поле и сохранить изменения.
  • [ ] При удалении операции появляется подтверждение «Вы уверены?».
  • [ ] После удаления операция исчезает из списка и не учитывается в отчетах.

AC для US-OP-06 (Комментарий)

  • [ ] Пользователь может добавить комментарий к операции (до 255 символов).
  • [ ] Комментарий отображается в списке операций.
  • [ ] Комментарий необязателен — операция сохраняется даже без него.

9. Сценарии использования (Use Cases)

Сценарий 1: Добавление расхода на аренду (авансовый платеж)

  1. Пользователь открывает форму добавления операции.
  2. Выбирает тип: «Расход».
  3. Вводит сумму: 45 000 ₽.
  4. Устанавливает date_fact: 25.10.2026 (день оплаты).
  5. Устанавливает date_period: 01.11.2026 (аренда за ноябрь).
  6. Выбирает проект: «ПВЗ Wildberries».
  7. Выбирает категорию: «Аренда».
  8. Добавляет комментарий: «Аренда за ноябрь».
  9. Нажимает «Сохранить».
  10. Операция сохраняется и отображается в списке.

Сценарий 2: Добавление дохода с задержкой выплаты (Wildberries)

  1. Пользователь открывает форму добавления операции.
  2. Выбирает тип: «Доход».
  3. Вводит сумму: 123 953 ₽.
  4. Устанавливает date_fact: 05.11.2026 (день получения денег).
  5. Устанавливает date_period: 31.10.2026 (работа выполнена в октябре).
  6. Выбирает проект: «ПВЗ Wildberries».
  7. Выбирает категорию: «Доход от ВБ».
  8. Нажимает «Сохранить».
  9. В отчете Cash Flow за ноябрь доход отображается как поступление.
  10. В отчете P&L за октябрь доход отображается как выручка октября.

Сценарий 3: Добавление налога вручную

  1. Пользователь получает квитанцию из ФНС на сумму 45 957 ₽.
  2. Открывает форму добавления операции.
  3. Выбирает тип: «Налог».
  4. Вводит сумму: 45 957 ₽.
  5. Устанавливает date_fact и date_period: 15.11.2026 (дата уплаты).
  6. Выбирает проект: «ПВЗ Wildberries».
  7. Выбирает категорию: «УСН 6%».
  8. Нажимает «Сохранить».
  9. Налог учитывается в отчете P&L за ноябрь как расход на налоги.
