ТЗ: Модуль «Дашборд и Отчеты» (P&L и Cash Flow)

1. Общее описание модуля

Модуль «Дашборд и Отчеты» — это ключевой аналитический экран приложения, где пользователь видит сводную картину финансов своих проектов. Модуль поддерживает два метода учета (кассовый и метод начисления) и два формата отображения (абсолютные значения и проценты), что позволяет пользователю анализировать денежные потоки и прибыльность бизнеса.

Цель модуля: Предоставить предпринимателю инструмент для сравнения периодов в одном проекте и сравнения проектов между собой, анализа структуры доходов и расходов, принятия бизнес-решений на основе данных.

3. Функциональные требования

3.1. Глобальные фильтры

IDТребованиеОписание
FR-DASH-01Фильтр «Период»Пользователь может выбрать период: Месяц (например, "Октябрь 2026"), Квартал (например, "Q4 2026"), Год (например, "2026"). По умолчанию — текущий месяц.
FR-DASH-02Фильтр «Проекты»Пользователь может выбрать: «Все проекты» или мультивыбор конкретных проектов из списка (чекбоксы). По умолчанию — все активные проекты.

FR-DASH-04Переключатель формата отображенияПользователь может переключать вид отчета: Абсолютные значения (₽) или Проценты (%). По умолчанию — абсолютные значения.

3.2. Структура отчета

IDТребованиеОписание
FR-DASH-05Отображение раздела «Доходы»Отображается строка «Доходы Итого» (сумма всех доходов за период) и детализация по каждой категории дохода с суммой/процентом.
FR-DASH-06Отображение раздела «Расходы»Отображается строка «Расходы Итого» (сумма всех расходов за период) и детализация по каждой категории расхода с суммой/процентом.
FR-DASH-07Отображение раздела «Налоги»Отображается строка «Налоги» (сумма всех операций с типом «Налог» за период). Детализация по категориям налогов (УСН, страховые взносы и т.д.).
FR-DASH-08Расчет «Чистая прибыль»Чистая прибыль = Доходы Итого − Расходы Итого − Налоги. Отображается отдельной строкой в конце отчета.
FR-DASH-09Расчет процентовВ режиме «Проценты» все суммы отображаются как % от «Доходы Итого». Доходы Итого = 100%.
FR-DASH-10Обработка деления на нольЕсли Доходы Итого = 0, проценты не рассчитываются. Отображается «0%» или «—» (прочерк).

3.3. Логика фильтрации по датам

IDТребованиеОписание
FR-DASH-11Кассовый метод (Cash Flow)При выборе «Кассовый метод» все суммы рассчитываются по полю date_fact (дата фактического движения денег). SQL: WHERE date_fact BETWEEN :start_date AND :end_date.
FR-DASH-12Метод начисления (P&L)При выборе «Метод начисления» все суммы рассчитываются по полю date_period (дата периода, к которому относится операция). SQL: WHERE date_period BETWEEN :start_date AND :end_date.

3.4. Детализация по категориям

IDТребованиеОписание
FR-DASH-13Группировка по категориямВ отчете доходы и расходы группируются по категориям. Каждая категория отображается отдельной строкой с суммой/процентом.
FR-DASH-14Сортировка категорийКатегории сортируются по убыванию суммы (от наибольшей к наименьшей).
FR-DASH-15Отображение только активных категорийВ отчете отображаются только категории с is_active = true. Скрытые категории не учитываются.

4. Бизнес-правила и логика расчетов

4.1. Формулы расчетов

Абсолютные значения (₽)

Доходы Итого = SUM(amount) FROM income_transactions WHERE (date_fact или date_period) BETWEEN :start AND :end
Расходы Итого = SUM(amount) FROM expense_transactions WHERE (date_fact или date_period) BETWEEN :start AND :end
Налоги = SUM(amount) FROM expense_transactions WHERE category.type = 'TAX' AND (date_fact или date_period) BETWEEN :start AND :end
Чистая прибыль = Доходы Итого − Расходы Итого − Налоги

Проценты (%)

Доходы Итого = 100%
Доход по категории X = (Сумма категории X / Доходы Итого) × 100%
Расходы Итого = (Расходы Итого / Доходы Итого) × 100%
Расход по категории Y = (Сумма категории Y / Доходы Итого) × 100%
Налоги = (Налоги / Доходы Итого) × 100%
Чистая прибыль = (Чистая прибыль / Доходы Итого) × 100%
Важно: Если Доходы Итого = 0, все проценты = 0% или — (избегаем деления на ноль).

5. Структура данных (связь с БД)

5.1. Таблицы для расчета

Доходы

SELECT 
    c.name AS category_name,
    SUM(it.amount) AS total_amount
FROM income_transactions it
JOIN categories c ON it.category_id = c.id
WHERE it.user_id = :user_id
    AND it.project_id IN (:project_ids)
    AND it.date_fact BETWEEN :start_date AND :end_date  -- для Cash Flow
    -- ИЛИ
    AND it.date_period BETWEEN :start_date AND :end_date  -- для P&L
    AND c.is_active = TRUE
GROUP BY c.id, c.name
ORDER BY total_amount DESC;

Расходы (включая налоги)

SELECT 
    c.name AS category_name,
    c.type AS category_type,  -- 'EXPENSE' или 'TAX'
    SUM(et.amount) AS total_amount
FROM expense_transactions et
JOIN categories c ON et.category_id = c.id
WHERE et.user_id = :user_id
    AND et.project_id IN (:project_ids)
    AND et.date_fact BETWEEN :start_date AND :end_date  -- для Cash Flow
    -- ИЛИ
    AND et.date_period BETWEEN :start_date AND :end_date  -- для P&L
    AND c.is_active = TRUE
GROUP BY c.id, c.name, c.type
ORDER BY total_amount DESC;

7. Критерии приемки (Acceptance Criteria)

AC для US-DASH-01, US-DASH-02 (Базовый отчет с переключением методов)

  • [ ] Пользователь может выбрать период (месяц/квартал/год) и проекты.
  • [ ] При выборе «Метод начисления» суммы рассчитываются по date_period.
  • [ ] При выборе «Кассовый метод» суммы рассчитываются по date_fact.
  • [ ] Отчет отображает: Доходы Итого, Расходы Итого, Налоги, Чистая прибыль.
  • [ ] Детализация по категориям отображается под каждой итоговой строкой.

AC для US-DASH-03 (Отображение в процентах)

  • [ ] При переключении в режим «Проценты» Доходы Итого отображаются как 100%.
  • [ ] Все остальные строки отображаются как % от Доходы Итого.
  • [ ] Если Доходы Итого = 0, проценты отображаются как «0%» или «—».
  • [ ] Чистая прибыль может быть отрицательной (убыток), процент тоже отрицательный.

AC для US-DASH-04 (Фильтрация по проектам)

  • [ ] Пользователь может выбрать «Все проекты» — отчет показывает сумму по всем проектам.
  • [ ] Пользователь может выбрать один проект — отчет показывает данные только по нему.
  • [ ] Пользователь может выбрать несколько проектов — отчет показывает агрегированные данные по выбранным.

AC для US-DASH-05 (Детализация по категориям)

  • [ ] Категории сортируются по убыванию суммы.
  • [ ] Скрытые категории (is_active = false) не отображаются в отчете.
  • [ ] Коммуналка и Интернет отображаются как разные строки (не объединены).

AC для US-DASH-06 (Сравнение периодов)

  • [ ] Пользователь может выбрать разные периоды и сравнить показатели (например, октябрь vs сентябрь).
  • [ ] При сравнении периодов отображаются оба периода рядом (опционально, если позволяет UI).

8. Сценарии использования (Use Cases)

Сценарий 1: Просмотр P&L за октябрь 2026 (метод начисления)

  1. Пользователь открывает раздел «Дашборд».
  2. Выбирает период: «Октябрь 2026».
  3. Выбирает проекты: «Все проекты».
  4. Переключатель метода: «Метод начисления (P&L)».
  5. Переключатель формата: «Абсолютные значения (₽)».
  6. Система загружает данные по date_period за октябрь 2026.
  7. Отображается таблица:
- Доходы Итого: 226 514 ₽

- Расходы Итого: 195 251 ₽

- Налоги: 0 ₽

- Чистая прибыль: 31 263 ₽

  1. Пользователь видит детализацию по категориям (Аренда: 55 000 ₽, Зарплата: 111 906 ₽ и т.д.).

Сценарий 2: Просмотр Cash Flow за октябрь 2026 (кассовый метод)

  1. Пользователь переключает метод на «Кассовый метод (Cash Flow)».
  2. Система пересчитывает данные по date_fact за октябрь 2026.
  3. Отображается таблица:
- Поступления: 135 953 ₽ (только те, что фактически пришли в октябре)

- Выплаты: 194 204 ₽ (только те, что фактически ушли в октябре)

- Сальдо: -58 251 ₽ (отток денег)

  1. Пользователь видит, что несмотря на прибыль по P&L, в октябре был отток денег (из-за авансовых платежей).

Сценарий 3: Анализ структуры расходов в процентах

  1. Пользователь переключает формат на «Проценты (%)».
  2. Система пересчитывает все строки как % от Доходы Итого.
  3. Отображается таблица:
- Доходы Итого: 100%

- Зарплата: 49.4%

- Аренда: 24.3%

- Интернет: 6.2%

- Коммуналка: 3.9%

- Расходники: 2.5%

- Расходы Итого: 86.2%

- Чистая прибыль: 13.8%

  1. Пользователь видит, что зарплата занимает почти половину доходов, и решает оптимизировать расходы.

Сценарий 4: Сравнение двух проектов

  1. Пользователь выбирает проекты: «ПВЗ Wildberries» и «Книги на Ozon».
  2. Система агрегирует данные по обоим проектам.
  3. Отображается сводный отчет:
- Доходы Итого: 350 000 ₽ (сумма по обоим проектам)

- Расходы Итого: 280 000 ₽

- Чистая прибыль: 70 000 ₽

  1. Пользователь видит общую картину по всем бизнесам.

9. Спорные моменты

№ВопросРешениеОбоснование
1UI/UX: Как реализовать переключатель «Кассовый метод / Метод начисления» на мобильном экране?Сегментированный контрол (Segmented Control) — горизонтальные кнопки-табы в виде одной плашки.Компактно, видно оба варианта сразу, переключение в 1 клик. Свитч слишком мелкий для длинных названий, выпадающий список требует 2 клика.
2UI/UX: Как реализовать мультивыбор проектов на мобильном экране?Модальное окно с чекбоксами + кнопка «Все проекты» сверху.Понятно на мобильном, быстро выбирается. Чекбоксы в выпадающем списке неудобны при длинном списке, поиск избыточен для 3-5 проектов.
3Backend: Нужно ли кэшировать результаты запросов дашборда?Не делать кэширование в MVP. Запросы к БД выполняются напрямую.Объем данных маленький (50-100 операций/месяц на пользователя). PostgreSQL сам кэширует в shared buffers. Риск рассинхрона: пользователь добавил операцию → дашборд показывает старые данные из кэша.
4Backend: Как обрабатывать ситуацию, когда у пользователя нет ни одной операции за выбранный период?Empty state с понятным UI-сообщением и кнопкой «Добавить операцию». Ошибки не возвращаются.Это нормальная ситуация (новый пользователь, первый месяц), а не ошибка системы.
5Frontend: Нужна ли визуализация (графики, диаграммы) в MVP?Только таблицы в MVP. Графики и диаграммы — в бэклог.Куратор в презентации показал только таблицы. MVP = минимальный продукт. Таблицы с процентами уже дают хорошую аналитику.
6Frontend: Нужен ли экспорт отчета в PDF/Excel?Не делать в MVP. Перенести в бэклог.Куратор прямо сказал: «В MVP можно не делать. Потом xls или гугл-таблицы».
